# HomeLab 展示与架构图交互设计草案

状态：讨论草案，尚未实施；交互方案为建议，待视觉原型验证。

## 目标与已确认事实

通过一张包含全部设备的立体场景介绍 HomeLab，再通过架构图和实践文章解释职责划分、网络链路与停机保障。

- 已有三个独立模型：机械革命 iMini、APC BK650M2-CH UPS、GL.iNet GL-MT3600BE 路由器；保留已认可的外形。
- 用户希望新增桌子或架子，把设备组织在同一场景；具体造型、比例与摆放尚未确定。
- 迷你主机以 Proxmox VE 为底层，包含主服务器虚拟机、Clash 旁路由虚拟机、Cloudflare Tunnel 虚拟机及其他虚拟机。
- 主服务器运行多个服务；实际服务清单、资源配置、网桥与路由规则待补充。
- UPS 通过 USB 接入 PVE 宿主机，由宿主机底层 Debian 上的 NUT 管理；用户已确认正常读取 UPS 状态，并完成断电自动关机实测。
- Home Assistant 属于笔记中的扩展方向，是否已部署未确认，不作为已完成能力展示。

## 页面结构

1. 概览：简短介绍、设备全景、设备选择与说明卡片。
2. 架构工作区：完整宽度的架构图、视图切换、节点说明。
3. 设计说明：职责划分、访问路径、故障影响及权衡。
4. 实践文章入口：UPS 配置与排障等详细记录。

## 点击后在哪里显示架构图

| 方案 | 优点 | 局限 | 建议 |
|---|---|---|---|
| 直接把立体模型替换成架构图 | 同一区域内切换，视觉集中 | 原模型区域可能偏窄，设备与内部结构难以同时参照 | 可作为后续可选视图 |
| 弹窗显示架构图 | 有沉浸感，可临时放大 | 长说明、移动端滚动、深链接和返回操作更复杂 | 仅用于放大已有图 |
| 右侧抽屉显示架构图 | 保留设备上下文 | 宽度有限，容不下 PVE、虚拟机和服务的多层关系 | 适合节点说明，不适合主图 |
| 页面内独立架构工作区 | 宽度充足，支持正文、锚点、分享和移动端 | 设备场景与主图有一定距离 | 推荐作为第一版 |

推荐采用“选中设备显示摘要，点击查看架构进入页面内工作区”。桌面端可以把概览做成左右布局，但架构工作区占用完整内容宽度。架构图不强塞进模型展示卡片。

首次点击设备只选中并高亮，显示明确的操作按钮，避免用户旋转模型时意外跳转。场景旁同时提供设备名称按钮，支持触屏和键盘操作。若后续希望单击直达，可保留设备列表作为明确的直达入口。

## 具体交互流程

### 迷你主机

1. 选中模型，摘要显示“Proxmox VE / 虚拟机与服务”，提供“查看系统架构”。
2. 点击按钮，将地址定位到 `#compute`，滚动到架构工作区，显示部署结构。
3. 主图默认展开 PVE 和三个核心虚拟机；主服务器内部先展示服务分组，其他虚拟机显示为可展开的“其他虚拟机 …”。
4. 点击虚拟机或服务节点，更新图下方说明区；桌面宽度充足时可使用旁栏。说明包含职责、设计理由、故障影响与相关文章。
5. 点击“返回设备全景”，回到场景并保留先前视角及设备选择。

### UPS

1. 选中 UPS，摘要显示“宿主机 NUT 监控 / 断电关机已实测”。
2. 点击“查看停机保障”，定位到 `#power`，显示 UPS、USB、NUT、PVE 与虚拟机的关系。
3. 分别提供“连接关系”和“停机过程”；过程步骤需要对照实际配置与日志整理，不凭空补全实测细节。
4. 提供 UPS 实践文章入口，正文再给出配置、排障与验证记录。

### 路由器

选中后显示型号和基础职责；“查看网络链路”进入 `#network`。物理路由器与虚拟旁路由分别表示；主路由、默认网关及实际出站策略未确认前，不画成既定关系。

### 地址与状态

- `#compute`、`#network`、`#power` 作为稳定、可分享的入口，直接打开时显示对应内容。
- 浏览器前进与后退同步章节状态，不为每次节点高亮生成历史记录。
- 章节始终保留标题和文字摘要，无 JavaScript 时仍可阅读并访问相关文章。
- 自动滚动考虑固定导航高度；支持减少动态效果的系统偏好。通过按钮进入章节时，焦点移动到目标标题。

## 架构图内容与表达

同一套设备与虚拟机数据支持多个视图；每个视图只强调一种关系。

| 视图 | 核心内容 | 表达重点 |
|---|---|---|
| 部署结构 | 物理主机 → PVE → 虚拟机 → 服务 | 包含关系、职责边界与资源组织 |
| 入站访问 | 访问者 → Cloudflare → Tunnel 虚拟机 → 指定服务 | 访问路径，实际鉴权策略另行确认 |
| 出站访问 | 主服务器 → Clash 旁路由 → 外部网络 | 按实际代理或路由配置绘制，不默认所有流量经代理 |
| 停机保障 | UPS → USB → NUT → PVE → 虚拟机 | 区分供电、状态通信与关机控制 |

图中使用明确图例、箭头标签与实线/虚线区别，不单靠颜色表达含义。部署结构采用嵌套容器，避免用网络箭头表达包含关系。其他虚拟机和服务清单逐步展开；视图切换时保留当前选择，若节点不在该视图中则清除选择并显示该视图摘要。

设计说明围绕实际问题展开：为什么拆分虚拟机、依赖如何组织、网络组件故障影响哪些服务、如何备份和恢复。多台虚拟机仍共享单台物理主机；职责拆分不等于高可用，网络隔离也需要实际策略支撑。

## UPS 文章整理边界

建议标题：《基于 NUT 的 Proxmox VE 断电停机保障实践》。结构为背景、apcupsd 异常、排查与迁移、最终配置、断电验证、限制与后续改进。

可确认结果为状态读取正常、断电自动关机已实测。每台虚拟机是否正常退出、数据是否完整、总关机耗时与恢复供电后的启动行为，尚无详细记录，后续补证据再写成验证结论。

原笔记混合建议、推测和实际操作。有关型号固件、93% 阈值、驱动误解析等原因，需要来源或日志佐证。截断命令、旧配置和强制停机测试命令不能直接复制成最终指南；最终参数应以当前有效配置为准。公开文章不包含密码、隧道令牌及其他凭据。

## 实现方向与实施顺序

技术建议：现有 CSS 3D 设备组成统一场景，SVG 配合少量 JavaScript 实现架构工作区，Hugo 管理内容与文章。模型、样式和脚本需封装，统一尺寸与坐标；不修改主题子模块，不增加后端。此处尚未锁定具体组件接口。

1. 先做静态交互线框：场景占位、设备选择、完整宽度架构图、节点说明和返回入口，验证阅读流程。
2. 确定桌子或架子造型与实际设备比例，整合三个模型。
3. 补充真实服务、网络配置与 NUT 停机证据，完成图与文章。
4. 正式实施前建立 OpenSpec 变更；接入 Hugo 后验证桌面、手机、键盘、锚点直达、浏览器历史及静态构建。

手机端将场景、设备选择和图依次排列；主图采用纵向分层布局，避免整张桌面图缩到文字无法阅读。图的放大是补充功能，职责说明始终可直接阅读。
