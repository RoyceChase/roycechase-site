# Design

## Context

见 proposal.md。当前采用 Blowfish profile 首页、light 默认外观和自动系统切换；主题已有 css/custom.css 资源加载入口。改动跨首页、通用导航与文章排版，需要明确样式边界。

## Goals / Non-Goals

Goals：建立集中维护的颜色与间距变量，仅对需要调整的布局使用项目扩展。

Non-Goals：不引入 UI 框架、字体服务或新运行时，不在本次制作头像、机柜或新增内容页面。

## Decisions

1. 默认 dark，关闭自动系统切换，保留主题手动切换和已有偏好。相比固定深色 CSS，此方案让浅色模式继续完整工作。
2. 配色建议：背景 #161617、面板 #1c1c1e、边框 #303033、标题 #f5f5f7、正文 #b0b0b8、蓝色 #2997ff。数字是依据截图给出的实现起点，需在渲染验证时调整；浅色模式使用独立变量。
3. 优先使用 Blowfish 原生 header 和 homepage 参数；profile 布局无法提供左对齐门户结构时，仅增加项目自有 homepage custom partial。保留现有简介与文章内容，入口只链接已有路径。
4. 用 assets/css/custom.css 集中维护必要样式；导航圆角约 20px、细边框、桌面内容最大宽度约 1200px，标题用 clamp 响应式字号。先检查生成页面的真实结构，再使用窄作用域选择器，避免覆盖搜索弹层和移动菜单。
5. 不以纯黑、炫光或装饰性背景替代参考中的低饱和风格。用户截图作为视觉依据；首页仍表达自己的身份，不复用 merox 的品牌与经历。

## Risks / Trade-offs

- [主题升级改变 DOM] → 减少依赖内部层级的选择器，记录扩展入口，升级后复查关键页面。
- [深色调降低可读性] → 检查正文、链接、代码和焦点对比，分别验证深浅色。
- [历史浏览器偏好影响默认效果] → 用无已保存偏好的会话验证首次深色，同时测试偏好保留。

## Migration Plan

实现后运行 Hugo 构建与本地服务器，检查 1440px 和 375px 首页、文章及列表截图与交互。部署沿用现有流程；回退本次配置、CSS 和首页扩展即可恢复原样式。
